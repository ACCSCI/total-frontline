# 迁移方案与验收清单 — P0 → 主工程

版本：v0.1
基线：`23ce27d chore: baseline before campaign migration to main`

原则：

1. 主工程是唯一战场。
2. 旧死斗模式始终可玩，任何阶段不破坏。
3. 迁移分批提交，每阶段必须通过用户验收后才能进入下一阶段。
4. P0 副本只作为参考实现，最终删除。
5. 共享数据只存一份，不允许两边复制后各自修改。
6. **统一 WebGPU-first 渲染，WebGL2 仅作兼容回退，不保留两套并行内容。**
7. **WebGPU 替换只发生在渲染层；建模、手感、动画一律保持不变：**
   - 建模：继续使用主工程现有视模、士兵 rig、地图与道具，不重新制作。
   - 手感：移动速度、瞄准、后坐、换弹、FOV、枪声、伤害全部沿用主工程数值。
   - 动画：视模动画、敌人骨骼/摆动、AI 行为全部以主工程为唯一来源。
8. 迁移验收必须包含“同场景 A/B 对照”，旧 WebGL2 与新 WebGPU 画面/手感不能出现可感知差异。

---

## 一、总体路线

```text
阶段 0  冻结与分支
阶段 1  构建系统共存：Vite + 旧 tsc 构建并存
阶段 2  渲染器共存：旧 WebGL2 死斗 + 新 WebGPU 战役双入口
阶段 3  共享数据层：武器/任务/音频/平衡参数单一来源
阶段 4  战役系统迁入：导演、目标、检查点、双武器、投掷、掉落、HUD
阶段 5  单人系统复用：移动、视模、AI、音频、敌人 rig
阶段 6  第一关「鹰落」集成
阶段 7  总验收、切换主入口、删除 P0
```

## 二、阶段计划

### 阶段 0：冻结与分支

- 保留 `23ce27d` 为回滚点。
- 创建分支 `feature/campaign-migration`。
- 记录旧游戏冒烟结果作为回归基准。

验收：
- [ ] 分支创建成功
- [ ] `npm run typecheck` 通过
- [ ] 旧死斗模式浏览器试玩正常
- [ ] 旧 P0 原型仍可运行

---

### 阶段 1：构建系统共存

目标：一个仓库同时构建两套产物。

- 根目录引入 Vite。
- 保留 `tsconfig.json` 旧构建，产物继续输出 `dist/js/game.js`。
- P0 代码迁移至 `src-next/`，作为 Vite 入口 `campaign/index.html`。
- 产物：
  - 旧死斗：`dist/index.html`
  - 战役：`dist/campaign/index.html`
- CI 同时跑两套 typecheck / build。

验收：
- [ ] `npm run build:legacy` 成功
- [ ] `npm run build:campaign` 成功
- [ ] 旧模式加载无报错
- [ ] 战役入口加载无报错
- [ ] 一个命令完成双构建

---

### 阶段 2：渲染器共存

目标：两个入口互不干扰。

- `src-next/renderer`：WebGPU-first，WebGL2 回退。
- `src-next/level`：黑森林河谷地图、雨、水洼、屏幕水滴、天空。
- `src-next/sequencer`：即时演算开场。
- 旧渲染器不动。

验收：
- [ ] WebGPU 入口 1080p 60fps
- [ ] WebGL2 回退可用
- [ ] 旧死斗模式帧率无回归
- [ ] 双入口同时打开资源不冲突

---

### 阶段 3：共享数据层

目标：规则只有一份。

共享文件：

- `shared/weapons.json`：武器 id、名称、弹匣、伤害、射速、自动模式
- `shared/missions.json`：20 关结构、第一关目标、拾取点、敌人配置
- `shared/loadout.json`：双武器规则、投掷物上限、掉落表
- `shared/audio.json`：程序化音频参数

旧工程与 `src-next` 都只读取共享数据，禁止内置第二份数值。

验收：
- [ ] 旧工程武器数值迁移到共享数据
- [ ] P0 武器数值删除本地定义
- [ ] 修改共享数据，两处表现同时变化
- [ ] 数据 schema 校验通过

---

### 阶段 4：战役系统迁入

从 P0 迁入并改造：

- 战役导演：目标链、触发区域、检查点
- 双武器槽：两把武器，任意组合，F 替换当前槽位
- 敌人掉落：弹药自动拾取，武器可 F 拾取
- 弹药补给点
- 投掷物：Q 战术、G 杀伤，上限各 3
- 无连杀奖励
- HUD：武器槽、弹药、投掷物、拾取提示、准星
- 调试模式：F2 点选、滚轮调高、G 一键贴地、L 日志

验收：
- [ ] 两把武器槽，第三槽不存在
- [ ] F 只替换当前槽
- [ ] 敌人死亡掉落弹药和武器
- [ ] 补给点自动补弹
- [ ] Q/G 投掷上限 3
- [ ] 剧情模式无连杀 UI
- [ ] HUD 全部中文提示

---

### 阶段 5：单人系统复用

这一阶段是核心工作量，按系统逐项迁移：

- 移动：从 `23-player-update.ts` 迁入滑铲、蹲、卧倒、翻越、侧身
- 视模：从 `15/16/24-*.ts` 迁入完整枪模、换弹、瞄准
- AI：从 `18/21/22-*.ts` 迁入班组 AI、巡逻、掩体、包抄
- 音频：从 `01/01b/01c-*.ts` 统一音频总线
- 敌人 rig：以 `18-enemies.ts` 为唯一来源，替换 P0 移植版
- 地图：主工程地图构建器迁入新架构，或保持旧架构兼容层

验收：
- [ ] 完整视模在第一关可见
- [ ] 换弹、瞄准、射击手感与单人模式一致
- [ ] 敌人 AI 与单人模式行为一致
- [ ] 敌人模型来自主工程 rig
- [ ] 枪声、脚步、环境音与单人模式一致
- [ ] 不破坏旧死斗模式

## 三、风险与对策

| 风险 | 对策 |
|---|---|
| 旧工程与新渲染器类冲突 | 双入口隔离，不共享运行时对象 |
| r128 → r185 API 差异 | 逐文件适配，不整包替换 |
| 视模/AI 迁移工作量大 | 按阶段验收，先框架后手感 |
| 地图资产不兼容 | 战役地图先走新架构，旧图保留 |
| 双构建变慢 | 并行构建，CI 缓存 |
